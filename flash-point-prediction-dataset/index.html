ML-ready chemistry datasets: notes

A flash point prediction dataset you can actually train on

2026-10-31

Flash point matters for shipping classification, solvent selection and process safety, but clean, open, machine-readable measurements are hard to find. Most QSPR papers use datasets of a few hundred to a couple of thousand compounds; the data are often behind a paywall or in a PDF table.

The best open starting point I know of is the integrated dataset released with Sun et al.'s 2020 paper on graph neural networks for flash point. We checked it for duplicate structures and conflicting measurements, then evaluated a simple baseline model.

The source

Sun X, Krakauer NJ, Politowicz A, et al. Assessing Graph-based Deep Learning Models for Predicting Flash Point. Molecular Informatics 2020, 39, 1900101, doi:10.1002/minf.201900101.

Data: Sun et al., Data for Assessing Graph-based Deep Learning Models for Predicting Flash Point, figshare, doi:10.6084/m9.figshare.9275210. License: CC BY 4.0.

The figshare record has one data file, integrated_dataset_public.csv, with 14,696 rows, each with a SMILES string, a flash point and a source tag. The rest of the record is model outputs from the paper.

What is in the raw file

The file combines earlier literature datasets with catalog data. By source tag: le15 (8,843 rows), pubchem (1,741), carroll11 (937), katritzky07 (739), "hazardous materials" (364), and smaller sets such as carroll10, mathieu14, patel10, chen14, mathieu12, wang11 and pan13. There are also small Gelest catalog subsets for metal-organics, silanes, tin and germanium compounds.

That has a few consequences.

Pitfalls

The same compound appears many times

14,696 rows collapse to 8,481 unique canonical SMILES. Because the sub-datasets overlap, a random row-level split will put the same molecule in train and test, which inflates your score. Aggregate by structure first.

Sources disagree

After aggregation, 649 compounds have values that differ by more than 10 K across sources. Some of that is real measurement spread; some of it is almost certainly open-cup versus closed-cup methods, which typically give different numbers for the same liquid. The public CSV does not label the method per row, so you cannot separate them. A flag lets you at least see whether these compounds dominate your errors.

Not everything is a plain organic

Silanes, metal-organics, tin compounds and acids are in there (the source CSV marks them with is_* columns). If your target is ordinary organic solvents, you probably want to filter them out. If you keep them, expect poor extrapolation from a model trained mostly on C/H/N/O compounds.

Temperature units

The source CSV reports flashpoint in kelvin; a value such as 350.15 is in K, not °C. Convert once (°C = K − 273.15) and keep both, so nobody downstream subtracts twice.

The scaffold split is skewed

About 40% of the compounds are acyclic and share the empty scaffold, so a scaffold split puts them all in train. The scaffold test set ends up with a mean of 170.2 °C versus 106.7 °C for the random test set. That makes it more of an extrapolation test than a "new chemistry" test. The cluster split is the fairer check.

How we cleaned it

  1. Canonicalize SMILES with RDKit (largest fragment, uncharged). 14,696 rows → 8,481 unique structures; 3 failed re-parsing.
  2. Drop 8 inorganic or tiny species (we keep compounds with carbon and at least 2 heavy atoms): 8,470 compounds.
  3. Take the median flash point in Kelvin per compound, add Celsius, n_values, n_sources, the range and the main source tag.
  4. Flag the 649 compounds with more than 10 K disagreement.
  5. Carry over the source's is_silicon, is_metallic, is_tin and is_acid flags so you can filter.
  6. Add random, Bemis–Murcko scaffold and Butina cluster (Morgan r2, Tanimoto ≥ 0.4) splits, about 80/10/10.

Baselines

Random Forest, 300 trees, test set, °C. From stats.json:

Split Features RMSE MAE R²
random RDKit descriptors 33.3 18.5 0.799
random Morgan 2048 41.4 28.5 0.688
cluster RDKit descriptors 32.5 18.1 0.816
cluster Morgan 2048 42.0 30.4 0.692
scaffold RDKit descriptors 53.7 36.0 0.554
scaffold Morgan 2048 88.3 70.4 −0.204

Predicting the training-set mean: RMSE 74.2 (random), 76.2 (cluster), 111.9 (scaffold).

The Morgan model on the scaffold split still beats the training-set mean (RMSE 88.3 vs 111.9), but its R² is negative: it does worse than a constant equal to the test-set mean. This happens when the test set has a different target distribution and the features cannot extrapolate. Descriptors (which include things like molecular weight and polarity terms that correlate with volatility) hold up much better.

Quick start with the free preview

import numpy as np, pandas as pd
from rdkit import Chem
from rdkit.Chem import Descriptors
from sklearn.ensemble import RandomForestRegressor
from sklearn.metrics import mean_absolute_error

url = ("https://huggingface.co/datasets/woongworks/flashpoint-ml-ready-preview"
       "/resolve/main/flashpoint_preview_150.csv")
df = pd.read_csv(url)

# plain organics only, no flagged disagreements
df = df[~(df.is_silicon | df.is_metallic | df.is_tin) & ~df.disagreement_flag]

X = np.nan_to_num(np.array([[fn(Chem.MolFromSmiles(s)) for _, fn in Descriptors.descList]
                            for s in df.smiles]), posinf=0, neginf=0)
tr, te = (df.cluster_split == "train").values, (df.cluster_split == "test").values
rf = RandomForestRegressor(n_estimators=300, random_state=0).fit(X[tr], df.fp_C[tr])
print("test MAE (deg C):", mean_absolute_error(df.fp_C[te], rf.predict(X[te])))

On 150 rows the test set is tiny, so treat the printed number as a smoke test only.

Limits

  • Open-cup and closed-cup values are mixed and not labeled.
  • Literature and catalog values, not re-measured.
  • The paper mentions DIPPR and handbooks as upstream inputs to the integrated set; this pack only uses the CC BY 4.0 CSV the authors released on figshare.
