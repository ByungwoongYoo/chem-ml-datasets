ML-ready chemistry datasets: notes

A melting point dataset for machine learning: what's in the Bradley set and how to clean it

2026-10-31

If you search for a melting point dataset for machine learning, you mostly end up in one of two places: a paper's supplementary file with a few hundred compounds, or the Jean-Claude Bradley Open Melting Point Dataset. The Bradley set is a useful starting point. It is large, it has SMILES, and it is released as CC0, so you can use it for anything. The raw file needs cleaning before you load it into a model and call fit().

We describe the source, the problems in the raw file and the cleaning steps, then report Random Forest results as a baseline for comparison.

The source

Bradley, Williams and Lang, Jean-Claude Bradley Open Melting Point Dataset, figshare (2014), doi:10.6084/m9.figshare.1031637. License: CC0 1.0.

It pulls values from several places: PHYSPROP, the Alfa Aesar catalog, handbooks and papers. Combining these sources gives the dataset its size, but also leaves inconsistencies to resolve. The file we started from has 28,645 rows.

Pitfalls in the raw file

Repeated measurements

Many compounds appear several times with different values from different sources. If you keep every row and split randomly, the same molecule can sit in train and test, and your test error looks better than it should.

Curator "do not use" flags

The dataset flags 377 rows as unreliable; those flags are easy to miss if you only read the SMILES and temperature columns.

Rows you might not want to redistribute

865 rows are sourced from DrugBank. The dataset itself is CC0, but we dropped those rows anyway to keep the licensing simple for anyone who builds on the result.

Unparsable structures

236 rows did not survive RDKit parsing and standardization.

Sources that disagree

After merging, 389 compounds have values from different sources that differ by more than 10 °C. Keep a record of them: they are often behind your worst errors.

A scaffold split that is harder than it looks

Scaffold groups in this set are very uneven. The biggest one is plain benzene (27% of compounds), and acyclic molecules, which all share the empty Bemis–Murcko scaffold, are another 15%. A scaffold split that sends the largest groups to train leaves the test set made of rarer ring systems, and those happen to melt higher on average: the scaffold test mean is 156.0 °C versus 102.8 °C for the random split. Keep that in mind before you read too much into a scaffold-split number.

How we cleaned it

  1. Drop the "do not use" rows, the DrugBank-sourced rows and unparsable SMILES. That leaves 27,167 measurements.
  2. Standardize each structure with RDKit and group measurements by structure.
  3. Take the median melting point per structure and record how many values and sources it came from, plus the min–max range.
  4. Flag (not delete) compounds where sources disagree by more than 10 °C.
  5. Keep organic compounds. The final ML set is 19,530 compounds.
  6. Add three split columns at roughly 80/10/10: random, Bemis–Murcko scaffold, and a cluster split (Butina clustering on Morgan fingerprints).

Baseline numbers

Random Forest, 300 trees, test set, °C. All numbers come from the pack's stats.json.

Split Features RMSE MAE R²
random RDKit descriptors 40.4 29.1 0.805
random Morgan 2048 49.1 35.4 0.712
cluster RDKit descriptors 43.3 32.8 0.749
cluster Morgan 2048 54.9 42.1 0.598
scaffold RDKit descriptors 54.2 41.0 0.476
scaffold Morgan 2048 72.1 53.9 0.072

Predicting the mean gives an RMSE of 91.4 (random), 86.8 (cluster) and 98.1 (scaffold).

Two things stand out. Descriptors beat Morgan bits on every split here. And the Morgan model barely beats the mean on the scaffold split (R² 0.072), which tells you that fingerprint-based models are mostly matching substructures they have already seen. If you report only random-split results for a new model, check its performance on the cluster split as well.

Try it on the free preview

A 150-row sample with the same columns (including the three split columns) is on Hugging Face. 150 rows is far too small to benchmark on, but it is enough to check your pipeline end to end.

import numpy as np, pandas as pd
from rdkit import Chem
from rdkit.Chem import Descriptors
from sklearn.ensemble import RandomForestRegressor
from sklearn.metrics import mean_absolute_error

url = ("https://huggingface.co/datasets/woongworks/melting-point-ml-ready-preview"
       "/resolve/main/mp_ml_ready_sample_150.csv")
df = pd.read_csv(url)

def feats(smi):
    m = Chem.MolFromSmiles(smi)
    return [fn(m) for _, fn in Descriptors.descList]

X = np.nan_to_num(np.array([feats(s) for s in df.smiles]), posinf=0, neginf=0)
y = df.mp_C.values

split = "cluster_split"          # try random_split / scaffold_split too
tr, te = (df[split] == "train").values, (df[split] == "test").values
rf = RandomForestRegressor(n_estimators=300, random_state=0).fit(X[tr], y[tr])
print("MAE (deg C):", mean_absolute_error(y[te], rf.predict(X[te])))

# look at the compounds where sources disagree
print(df[df.disagreement_flag][["name", "mp_C", "range_C"]].head())

Limits

  • Values come from mixed sources and were not re-measured.
  • Decomposition and sublimation notes are not modeled.
  • Not validated against an independent external set.
