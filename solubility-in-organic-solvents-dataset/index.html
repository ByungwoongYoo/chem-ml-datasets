Solubility in organic solvents: an ML dataset and the limits of random splits

2026-10-31

There are plenty of public datasets for aqueous solubility. Far fewer cover solubility in organic solvents, which is needed for crystallisation, formulation and choosing reaction solvents. The largest open collection I know of with measured values across many solvents is the Open Notebook Science (ONS) Challenge solubility dataset that Jean-Claude Bradley and colleagues collected.

This post covers what is in it, how to clean it for machine learning, and one problem that is specific to solute–solvent data: the way you split it changes the result more than the model does.

The source

Bradley J-C, Guha R, Hooker B, Koch SJ, Lang A, Neylon C, Williams AJ. Open Notebook Science Challenge Solubility Dataset. figshare (2015), doi:10.6084/m9.figshare.1514952. License: CC BY 4.0.

It has 9,730 rows. Each row records a solute, a solvent and a concentration, along with a citation to a paper, notebook page or supplier table. Part of it was measured by students and volunteers in an open notebook; part was gathered from the literature.

What to remove, and why

The raw file mixes several things you probably do not want in one model:

  • Water and water mixtures (4,632 rows). Almost half the file. If you want an organic-solvent model, take them out; aqueous solubility behaves differently and has better dedicated datasets.
  • "DONOTUSE" rows (91). Marked by the curators. Easy to miss.
  • PEG400 as a solvent (98 rows). It is a polymer, so one SMILES cannot describe it.
  • Solutes that react with the solvent (16). These entries do not represent solubility measurements.
  • Liquid solutes (74). We kept solid solutes only, so every value is the saturation concentration of a solid.
  • Missing or non-positive concentrations (61) and temperatures stated outside 20–30 °C (24).
  • Unparsable SMILES (69).

That leaves 4,665 measurements. Merging repeats of the same solute–solvent pair (median of log10 mol/L) gives 3,776 pairs: 591 solutes in 174 solvents. 34 pairs have repeats that disagree by more than 0.5 log units; they are flagged.

Most pairs (3,310 of 3,776) come from a single source. Temperature is "about room temperature" and often not stated. Large polycyclic aromatics are over-represented (anthracene alone has 86 pairs, pyrene 75). The most common solvents are 1-octanol (262 pairs), methanol (245), ethanol (229), acetonitrile (142) and DMSO (133). And 93 DMSO rows come from a solvent supplier's table rather than a peer-reviewed paper; the long file keeps the citation so you can filter by it.

The split problem

With solute–solvent pairs, a random split puts the same solute in train and test, just dissolved in a different solvent. Solubility of one compound across solvents is strongly correlated, so the model can do well by remembering the solute.

To see how much that matters, we built three splits:

  • random_split: by pair.
  • scaffold_split: by the solute's Bemis–Murcko scaffold, so no solute appears in more than one split.
  • cluster_split: by Butina clusters of solutes (Morgan r2, Tanimoto ≥ 0.4).

Baselines

Random Forest, 300 trees, test set, logS in log10 mol/L. Solvents are described with RDKit descriptors in both models. From stats.json:

Split Solute Morgan + solvent desc. Solute desc. + solvent desc. Mean baseline RMSE
random R² 0.743, RMSE 0.478 R² 0.767, RMSE 0.455 0.944
scaffold R² 0.091, RMSE 1.042 R² 0.261, RMSE 0.939 1.186
cluster R² 0.207, RMSE 0.624 R² 0.173, RMSE 0.637 0.799

R² drops from about 0.75 to about 0.2 once the model has to predict solutes it has not seen. Most of the "accuracy" on the random split is solute memorisation. If you are building a model to rank solvents for a known compound, the random split is roughly your use case. For new compounds, the scaffold and cluster results are more relevant and show substantial room for improvement.

Try it

import numpy as np, pandas as pd
from rdkit import Chem
from rdkit.Chem import Descriptors

url = ("https://huggingface.co/datasets/woongworks/ons-nonaq-solubility-ml-ready-preview"
       "/resolve/main/ons_nonaq_preview_150.csv")
df = pd.read_csv(url)

def desc(smi):
    m = Chem.MolFromSmiles(smi)
    return [fn(m) for _, fn in Descriptors.descList]

# featurize each unique molecule once, then join solute + solvent vectors
cache = {s: desc(s) for s in set(df.solute_smiles) | set(df.solvent_smiles)}
X = np.nan_to_num(np.array([cache[a] + cache[b]
                            for a, b in zip(df.solute_smiles, df.solvent_smiles)]),
                  posinf=0, neginf=0)
y = df.logS_M.values

# how many test solutes also appear in train? (leakage check)
for split in ["random_split", "scaffold_split"]:
    tr = set(df.solute_smiles[df[split] == "train"])
    te = set(df.solute_smiles[df[split] == "test"])
    print(split, "test solutes seen in train:", len(te & tr), "/", len(te))

The final loop counts how many test solutes also appear in the training set. Run this check before interpreting results from a solute–solvent dataset.

Limits

  • Mostly single-source pairs; values were not re-measured.
  • Room temperature only, often not stated exactly.
  • Coverage is uneven: a few solutes and solvents dominate.
