ML-ready chemistry datasets: notes

Henry's law constant dataset for machine learning: cleaning Sander's compilation

2026-10-31

For a QSPR or ML model of Henry's law constants in water, we would start with Rolf Sander's compilation. It is huge, carefully referenced and openly licensed. It is also a reference work, built for looking values up rather than for training models. Turning the compilation into a clean smiles, y table requires structure mapping, filtering by value type and checking unit conventions.

We describe those steps and report the baseline results.

The source

R. Sander, Compilation of Henry's law constants (version 5.0.0) for water as solvent, Atmos. Chem. Phys. 23, 10901–12440 (2023), doi:10.5194/acp-23-10901-2023. The data is downloadable from henrys-law.org. The article is distributed under CC BY 4.0, and the full data table is in its appendix.

The database we parsed has 46,434 values from 995 publications, for organic and inorganic species.

Pitfalls

Unit conventions

Henry's law constants are reported in many forms: solubility constants (concentration in water over partial pressure) and volatility constants (the inverse), with or without dimensions. Sander standardizes to a solubility constant Hscp in mol m⁻³ Pa⁻¹. If you merge in values from anywhere else, check which convention they use; mixing a constant with its inverse flips the sign of the log and destroys the model.

Not every value is a measurement

Each value in the compilation has a type code. Some are experimental or derived from experimental data, some are cited second-hand, and some are QSPR predictions (Q) or estimates (E). There are also values of unknown origin (?) and values the compiler marks as wrong (W). Training on QSPR outputs means learning someone else's model. We kept only the experimental-type codes (M, V, T, R, L, C, X) and dropped Q, E, ? and W. That left 13,709 of 46,434 values.

No SMILES in the source

Species are identified by name, CAS and InChIKey. We mapped InChIKeys to structures using PubChem and the EPA OPERA QSAR-ready set. We mapped 13,591 of the retained values to molecular structures.

Temperature

The ML target is the value at 298.15 K. The temperature-dependence term is kept in the long file but not modeled.

Huge dynamic range

In log10 units the targets run from −9.1 to 15.69, with a standard deviation of 3.35. The wide target range makes it easier to obtain a high R². Check RMSE as well.

Disagreement

For 185 compounds, the reported values disagree by more than one log unit (standard deviation > 1). We flag them rather than drop them.

The scaffold split is a different question

57% of compounds are acyclic (small volatile molecules) and share the empty Bemis–Murcko scaffold. In a scaffold split they all land in train. The scaffold test set then has a very different target mean: train −2.06, test +1.84 in log10 units. That makes it a hard extrapolation test rather than a fair "new chemistry" test. Use the cluster split for that.

How we cleaned it

  1. Parse all 46,434 values from the SQL release.
  2. Keep experimental-type values (M, V, T, R, L, C, X): 13,709.
  3. Convert to log10 Hscp at 298.15 K, map InChIKeys to structures, keep the largest fragment.
  4. Merge duplicates per structure by median, recording the number of values, number of references and standard deviation.
  5. Keep organic compounds with at least 2 heavy atoms: 4,228 compounds. (A separate file keeps 4,296 species including inorganics.)
  6. Add random, scaffold and cluster (Butina, Morgan r2, Tanimoto distance 0.6) splits.

Baselines

Random Forest, 500 trees, test set, log10 units. From stats.json:

Split Features RMSE MAE R²
random RDKit descriptors 1.117 0.540 0.893
random Morgan 2048 1.347 0.738 0.844
cluster RDKit descriptors 1.028 0.584 0.892
cluster Morgan 2048 1.670 0.960 0.714

Predict-the-mean RMSE: 3.412 (random), 3.177 (cluster), 5.092 (scaffold).

An MAE of around half a log unit on the random and cluster splits corresponds to a factor of about three in the constant itself. That may be acceptable for some environmental fate applications; check whether it is adequate for the chemical class and quantitative task you have in mind.

Quick look with the free preview

import numpy as np, pandas as pd
from rdkit import Chem
from rdkit.Chem import Descriptors
from sklearn.ensemble import RandomForestRegressor

url = ("https://huggingface.co/datasets/woongworks/henry-law-ml-ready-preview"
       "/resolve/main/henry_ml_ready_sample_150.csv")
df = pd.read_csv(url)

# which value types does each compound rest on? (codes are concatenated, e.g. "M", "VX")
print(df.htypes.value_counts().head())

# compare target distributions across splits before modelling
for split in ["random_split", "scaffold_split", "cluster_split"]:
    print(split, df.groupby(split).log10_Hscp_298K.mean().round(2).to_dict())

X = np.nan_to_num(np.array([[fn(Chem.MolFromSmiles(s)) for _, fn in Descriptors.descList]
                            for s in df.smiles]), posinf=0, neginf=0)
tr = (df.cluster_split == "train").values
rf = RandomForestRegressor(n_estimators=500, random_state=0)
rf.fit(X[tr], df.log10_Hscp_298K[tr])

The per-split means are worth printing every time. On the full set, the scaffold split's shift shows up immediately.

Limits

  • Values come from 995 publications of mixed quality; some value types are cited second-hand.
  • Only 298.15 K values are used as the target.
  • Not checked against an independent set of new measurements.
