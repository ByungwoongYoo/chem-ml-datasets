ML-ready chemistry datasets: notes

Where to download a logP dataset with SMILES (and what to check before you train on it)

2026-10-31

For logP modelling, a CSV with SMILES and experimental octanol–water partition coefficients is a useful starting point, provided it contains enough reliable measurements to train on. In practice the first file you find is often not logP at all, or it mixes measured and predicted values.

We use the open SangsterLogP dataset. Below, we describe the checks needed before training and report the baseline results.

First, make sure it is actually logP

A common mix-up: the "Lipophilicity" set in MoleculeNet is logD at pH 7.4, not logP. logD depends on ionisation at a given pH; logP describes the neutral species. For neutral compounds they are close; for acids and bases they can be far apart. If you train on logD and then use the model as a logP predictor (or the other way round), the errors on ionisable compounds will be systematic.

The second mix-up is predicted values. Many "logP" columns in public tables are cLogP or XLogP outputs. A model trained on another model's predictions will learn that model, including its blind spots.

The source we use

Cirino T, Sangster J, Charochkina L, Tetko I. SangsterLogP dataset. Zenodo, doi:10.5281/zenodo.19387552. Data descriptor in Scientific Data (2026), doi:10.1038/s41597-026-07357-2. License: CC BY 4.0.

It is a curated compilation of experimental octanol–water logP values for 23,520 entries, distributed as an Excel workbook. Besides logP it carries a separately reported "Lipophilicity" value, an ionisation-based class, the experimental method, pH and temperature where known, and a "Recommended" flag. The metadata helps you decide which rows to include.

Pitfalls in this data

logP and Lipophilicity are not always the same number

For about 94% of rows they match. The 1,343 rows where they differ are mostly in ionisation class M. If you want a clean neutral-species target, look at ion_class and logP_lip_delta before training.

Only some rows are "Recommended"

7,964 compounds carry the source's Recommended = yes flag. Training on all 23,512 is fine for a broad model, but it is worth checking whether your error drops on the recommended subset; if it does not, the noise is probably not where you think.

Method and pH are sparse

Shake-flask, HPLC and other methods are all in there, but many rows have no method or pH recorded. You can filter on exp_method when it is present; you cannot recover it when it is not.

Large molecules

284 compounds are in a class labelled "NC (>700Da)". If your use case is small-molecule drug-like chemistry, you may want to drop them.

Spreadsheet details

The workbook has several sheets (the main set, a Huuskonen set and a prospective set). Use the main sheet, and drop the 8 rows with non-numeric logP values.

How we cleaned it

  1. Read the main sheet, drop the 8 non-numeric logP rows: 23,512 left.
  2. Standardize SMILES with RDKit (largest fragment, uncharged, canonical). All 23,512 parsed.
  3. Merge by canonical SMILES (median); no duplicates remained after merging, and no compound needed a disagreement flag.
  4. Keep the source metadata columns (ion_class, recommended, exp_method, pH_num, bRo5, and so on) so you can filter.
  5. Add three split columns at about 80/10/10: random, Bemis–Murcko scaffold, and Butina clusters (Morgan radius 2, Tanimoto ≥ 0.4).

Baselines

Random Forest, 300 trees, test set, logP units. From the pack's stats.json:

Split Features RMSE MAE R²
random RDKit descriptors 0.656 0.467 0.848
random Morgan 2048 0.841 0.615 0.750
scaffold RDKit descriptors 0.919 0.686 0.613
scaffold Morgan 2048 1.164 0.882 0.379
cluster RDKit descriptors 0.895 0.645 0.722
cluster Morgan 2048 1.169 0.895 0.526

Predicting the mean gives RMSE 1.681 / 1.566 / 1.713 (random / scaffold / cluster). Note that RDKit's descriptor list includes Crippen MolLogP, so the descriptor model starts with a decent logP estimate as one of its inputs. That is fine for a baseline, but keep it in mind if you compare against a pure graph model.

Load the free preview

import pandas as pd
from rdkit import Chem
from rdkit.Chem import Crippen

url = ("https://huggingface.co/datasets/woongworks/sangster-logp-ml-ready-preview"
       "/resolve/main/sangster_logp_preview_150.csv")
df = pd.read_csv(url)

# keep rows where logP and the reported lipophilicity agree
neutral = df[df.logP_lip_delta.abs() < 1e-6]
print(len(df), "rows,", len(neutral), "with logP == lipophilicity")
print(df.ion_class.value_counts())

# how far off is plain Crippen logP on these rows?
neutral = neutral.assign(
    crippen=[Crippen.MolLogP(Chem.MolFromSmiles(s)) for s in neutral.smiles])
err = (neutral.crippen - neutral.logP).abs()
print("Crippen MAE vs experimental:", round(err.mean(), 3))

That last check is a good habit: if your trained model does not clearly beat Crippen on the cluster split, it has not learned much.

Metal complexes are a different problem

Organic logP models do badly on coordination compounds. If that is your area, we also packaged MetalLipoDB (Krasnov et al., Zenodo doi:10.5281/zenodo.23084573, CC BY 4.0): shake-flask logP for 3,885 metal complexes. For these complexes, the same Random Forest with RDKit descriptors reaches R² 0.535 on a random split and 0.282 on a scaffold split. Free preview: metallipo-logp-ml-ready-preview.
