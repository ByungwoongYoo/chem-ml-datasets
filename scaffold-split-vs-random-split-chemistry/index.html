Scaffold split vs random split in chemistry ML: the same model on 13 datasets

2026-10-31

If you train a molecular property model and split your data randomly, you are mostly measuring how well the model recognises molecules that look like ones it has already seen. That is sometimes what you want. Usually it is not: in real use, the molecules you care about are new ones.

The usual fix is a scaffold split. It is a good default, but it has its own failure mode that people rarely mention. We compare random, scaffold and cluster splits using the same simple model on 13 open experimental datasets to show how much the choice of split affects the results.

The three splits

Random split

Shuffle compounds, cut 80/10/10. Close analogues (a methyl vs an ethyl ester, say) end up on both sides. The model can score well by interpolating between near-duplicates.

Scaffold split

Compute each molecule's Bemis–Murcko scaffold (ring systems plus the linkers between them, side chains removed), group by scaffold, and assign whole groups to train, validation or test. The common convention, used in MoleculeNet-style code, is to put the largest groups in train and the rare scaffolds in test. Now no ring system in test has been seen in training.

Cluster split

Cluster molecules by fingerprint similarity (we use Butina clustering on Morgan radius-2 fingerprints with a Tanimoto threshold of 0.4) and assign whole clusters. This separates compounds by overall similarity rather than by ring system alone.

Every row drops from random to scaffold, often by a lot. Non-aqueous solubility goes from 0.767 to 0.261. Henry's law goes from 0.893 to 0.444. If you had only reported the random split, you would have overestimated how the model does on new chemistry.

The catch: scaffold splits can also mislead

For melting point, flash point, Henry's law and surface tension, the cluster and random splits give similar R² values; the scaffold split gives much lower values.

Scaffold groups are very uneven, and the biggest ones are simple. Acyclic molecules all share the same scaffold, the empty one: about 40% of the flash point set and 57% of the Henry's law set. In the melting point set the largest group is plain benzene (27%), with acyclic compounds another 15%. A "largest groups go to train" scaffold split puts all of those in train, so the test set is made only of rarer ring systems. That shifts the target distribution:

  • Melting point: test mean 156.0 °C on the scaffold split vs 102.8 °C on the random split.
  • Flash point: 170.2 °C vs 106.7 °C.
  • Henry's law (log10 units): train mean −2.06, test mean +1.84 on the scaffold split.

Part of the drop in the scaffold-split score comes from the test set's different label distribution. That is a separate consideration from predicting unfamiliar chemistry. A cluster split does not have this artefact as strongly, which is why we report all three.

The opposite also happens. For IL viscosity and AIE emission, the cluster split is the hardest. But their cluster test sets are small (50 and 28 compounds), so those numbers are noisy. Treat the result from one seed and 28 test compounds as preliminary.

Practical advice

  1. Report at least two splits. Random alone tells you very little about generalisation.
  2. Check the target distribution per split. Print the mean and standard deviation of y for train and test. If they differ a lot, say so.
  3. Look at the size of the largest scaffold groups (often benzene and the empty acyclic scaffold) before trusting a scaffold split.
  4. Freeze your splits as columns in the data file. Recomputing the splits with a different RDKit version or random seed changes the results and prevents a direct comparison.
  5. Use more than one seed when test sets are small.

A scaffold split in a few lines

from collections import defaultdict
import pandas as pd
from rdkit import Chem
from rdkit.Chem.Scaffolds import MurckoScaffold

def scaffold_split(smiles, frac=(0.8, 0.1, 0.1)):
    groups = defaultdict(list)
    for i, s in enumerate(smiles):
        m = Chem.MolFromSmiles(s)
        groups[MurckoScaffold.MurckoScaffoldSmiles(mol=m)].append(i)
    # largest scaffold groups first -> train
    ordered = sorted(groups.values(), key=len, reverse=True)
    n, out = len(smiles), {}
    cut1, cut2 = frac[0] * n, (frac[0] + frac[1]) * n
    filled = 0
    for idx in ordered:
        part = "train" if filled + len(idx) <= cut1 else (
               "valid" if filled + len(idx) <= cut2 else "test")
        for i in idx:
            out[i] = part
        filled += len(idx)
    return [out[i] for i in range(n)]

url = ("https://huggingface.co/datasets/woongworks/melting-point-ml-ready-preview"
       "/resolve/main/mp_ml_ready_sample_150.csv")
df = pd.read_csv(url)
df["my_scaffold_split"] = scaffold_split(df.smiles.tolist())
print("largest scaffold groups:", df.scaffold.fillna("<acyclic>").value_counts(normalize=True).head(3).round(3).to_dict())
print(df.groupby("my_scaffold_split").mp_C.agg(["count", "mean"]))
print(df.groupby("random_split").mp_C.agg(["count", "mean"]))

Run it and compare the per-split means. On a full dataset you will usually see the scaffold test mean drift away from the overall mean.
